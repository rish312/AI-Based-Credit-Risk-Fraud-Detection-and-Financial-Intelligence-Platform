# ML Prediction Platform — Implementation Plan

## Goal

Build a full-stack ML prediction platform in `/Users/ekanshsukla/Desktop/credit_riskml` that:

1. Trains three independent models (credit risk, fraud detection, customer segmentation) on synthetic data
2. Serves all three via a FastAPI REST API with auth, audit logging, and rate limiting
3. Explains every prediction with SHAP (TreeSHAP for supervised models, surrogate for clustering)
4. Surfaces everything in a React dashboard with unified scores, SHAP waterfall charts, a fraud review queue, and monitoring views

---

## User Review Required

> [!IMPORTANT]
> **Synthetic Data**: Since no real datasets are provided, all three models will be trained on realistic synthetic data generated by the pipeline. The data generators will produce distributions that mimic real-world patterns (class imbalance for fraud, correlated features for credit risk, distinct cluster shapes for segmentation). This is suitable for a demo/prototype — swap in real data later without changing any downstream code.

> [!IMPORTANT]
> **Simplified Feature Store**: Instead of deploying Feast (which requires infrastructure), the feature store will be a lightweight in-memory/SQLite layer that computes and caches features on demand. The interface is designed so Feast or Redis can be plugged in later.

> [!WARNING]
> **No Production Auth Provider**: Authentication uses JWT tokens with a local user store (SQLite). For production, swap to OAuth2/OIDC with an external IdP. The role-based access control (RBAC) layer is real and enforced.

### Component 2: Model Training

#### [NEW] [model.py](file:///Users/ekanshsukla/Desktop/credit_riskml/backend/ml/credit_risk/model.py)
- XGBoost classifier with Platt scaling (`CalibratedClassifierCV` with `method='sigmoid'`)
- Output: calibrated P(default), mapped to risk tiers: Low (0-0.15), Medium (0.15-0.4), High (0.4-0.7), Very High (0.7+)
- Saves: model artifact + calibrator + feature names + version metadata

#### [NEW] [model.py](file:///Users/ekanshsukla/Desktop/credit_riskml/backend/ml/fraud/model.py)
- Ensemble: XGBoost supervised classifier + IsolationForest anomaly detector
- Combined score: `0.7 * xgb_proba + 0.3 * (1 - isolation_forest_score)` (normalized)
- Three-tier decisioning: Auto-approve (<0.3), Manual review (0.3-0.7), Auto-decline (>0.7)
- Optimized for low latency: pre-compiled model, minimal feature transforms

#### [NEW] [model.py](file:///Users/ekanshsukla/Desktop/credit_riskml/backend/ml/segmentation/model.py)
- KMeans with k chosen by silhouette score (testing k=3..7)
- Surrogate: RandomForest classifier trained to predict cluster assignment → enables TreeSHAP explanations
- Segment profiling: auto-generates human-readable names from centroid feature analysis
- Output: cluster_id, cluster_name, membership_confidence (distance-based)

#### [NEW] [train.py](file:///Users/ekanshsukla/Desktop/credit_riskml/backend/ml/credit_risk/train.py) / [train.py](file:///Users/ekanshsukla/Desktop/credit_riskml/backend/ml/fraud/train.py) / [train.py](file:///Users/ekanshsukla/Desktop/credit_riskml/backend/ml/segmentation/train.py)
- Each: generate data → engineer features → train → evaluate → save artifacts with version metadata
- Credit risk: log AUC-ROC, calibration curve, Brier score
- Fraud: log precision/recall at each tier threshold, confusion matrix
- Segmentation: log silhouette score, cluster sizes, surrogate accuracy

### Component 3: Explainability (SHAP)

#### [NEW] [explainability.py](file:///Users/ekanshsukla/Desktop/credit_riskml/backend/ml/explainability.py)
- `explain_credit_risk(model, features)`: TreeSHAP → base_value + per-feature contributions
- `explain_fraud(model, features)`: TreeSHAP on the XGBoost component (the dominant signal)
- `explain_segmentation(surrogate_model, features)`: TreeSHAP on the surrogate classifier
- Output schema per model:
  ```json
  {
    "base_value": 0.08,
    "features": [
      {"name": "debt_to_income", "value": 0.45, "contribution": +0.12},
      {"name": "credit_utilization", "value": 0.82, "contribution": +0.08},
      ...
    ],
    "output_value": 0.35
  }
  ```
- Contributions are sorted by absolute magnitude for rendering

### Component 4: ML Prediction Engine (Orchestration)

#### [NEW] [engine.py](file:///Users/ekanshsukla/Desktop/credit_riskml/backend/ml/engine.py)
- `PredictionEngine` class: loads all three models at startup, holds references
- `predict(raw_input)`:
  1. Call `feature_store.get_features(raw_input)` — compute features once
  2. Dispatch all three models via `asyncio.gather()` with per-model timeout (fraud: 100ms, others: 2s)
  3. For each model result, call the SHAP explainability layer
  4. Aggregate responses: if a model times out or errors, return `{"status": "unavailable", "score": null}` for that model, with the others intact
  5. Package: `{prediction_id, timestamp, model_versions, credit_risk: {...}, fraud: {...}, segmentation: {...}}`
- Model versioning: each model dir contains `metadata.json` with `version`, `trained_at`, `metrics`
